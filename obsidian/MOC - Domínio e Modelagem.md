# MOC - Domínio e Modelagem

> Eixo do *o quê*: entender o problema antes da solução. É aqui que se descobre onde cortar o sistema — e toda decisão de arquitetura é consequência dessas fronteiras.

## Notas deste eixo

- [[Domain-Driven Design]] — Colocar o domínio — não o banco, nem o framework — no centro do desenho, com um modelo que o time todo consegue falar.
- [[Bounded Context]] — A fronteira onde um modelo faz sentido por completo — a mesma palavra pode significar coisas diferentes do outro lado dela.
- [[Linguagem Ubíqua]] — Um vocabulário único falado por negócio e código — se a reunião diz uma palavra e o código outra, o modelo já está mentindo.
- [[Entidade, Value Object e Agregado]] — As três peças táticas do DDD: o que tem identidade, o que é definido pelo valor, e até onde vai a fronteira que protege uma regra.
- [[Context Map]] — O mapa das relações entre contextos — quem é fornecedor, quem é cliente, quem só precisa de uma camada anticorrupção.
