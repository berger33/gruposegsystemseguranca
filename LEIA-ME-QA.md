# Grupo SEG System — prévia local para avaliação, NÃO produção

**Dois passos:** (1) baixe e extraia `seg-system-qa-local.zip`; (2) dentro da pasta extraída, execute `INICIAR-QA.bat` (Windows, duplo clique) ou `./INICIAR-QA.sh` no Terminal (macOS/Linux). Aguarde instalação/compilação e abra **http://localhost:3000**. Pare com Ctrl+C. É necessário **Node.js 22 com npm e internet** na primeira execução (dependências são instaladas com `npm ci`); não estão embutidos no ZIP. Em Linux/macOS, se necessário use `bash INICIAR-QA.sh`.

O lançador rejeita URLs de banco, diretórios externos de arquivos e arquivos `.env` conhecidos na pasta. Usa **PGlite local de esquema beta reduzido** em `.data/pglite`; não inicia Docker, PostgreSQL externo, SMTP, Ollama, túnel ou publicação. A aplicação pode conter telas/integrações demonstrativas e **não deve receber dados pessoais ou reais**. Admin funcional, RBAC completo, recuperação operacional, IA real e serviços externos não estão homologados; não encaminhe esta prévia como produção. Veja [relatório QA completo](docs/RELATORIO-CONSOLIDADO-TESTES.md), [pendências](docs/RELATORIO-PENDENCIAS-COMPLETO.md) e [gate de produção bloqueado](docs/PRODUCAO-GATE.md).

Para rodar somente os testes automatizados no código extraído, após instalar Node 22: `npm ci && npm test && npm run typecheck && npm run build`. Testes de PostgreSQL com clusters descartáveis exigem ferramentas/configuração à parte; **não** estão incluídos no caminho de 2 passos. O ZIP é artefato de código-fonte QA; build é gerado localmente. Não contém `.env*`, credenciais, banco, dependências `node_modules`, `.next`, logs ou artefatos ZIP antigos. O arquivo `.sha256` ao lado do ZIP permite conferir integridade da transferência, mas **não é assinatura digital** nem prova de procedência operacional.
