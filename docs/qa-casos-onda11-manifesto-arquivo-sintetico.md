## Limites e decisões

- `PLT-DEF-017` / **corrigido no runner QA, reteste negativo passou**: evento assíncrono de pool idle interrompia limpeza após falha do arquivo. Não alegar cleanup do primeiro negativo; depois de corrigir, ambos os clusters e o arquivo temporário foram removidos no `finally`. Eventos de erro agora marcam resultado 1 e não derrubam o processo antes da limpeza.
- O manifesto **não é autenticado/assinado**: trocar manifesto e bytes juntos não é detectado. Não há criptografia, KMS, armazenamento remoto, retenção/descarte, inventário total de arquivos, quiescência/snapshot consistente entre FS e DB sob escrita concorrente, comparação de documentos v2, teste de bytes via HTTP autenticado após restauração, PITR ou RPO/RTO. O dump **não** contém os bytes: a cópia sintética em pacote paralelo é uma etapa separada. O helper é de propósito limitado a **um** arquivo criado pelo runner, não aceita `CLIENT_DOCS_DIR` de operador e não deve ser usado como executor da API de backup.
- A API administrativa PLT-08 permanece **somente leitura/fail-closed** para criação/restauração; o ensaio QA não altera flags `success`/`is_restore_tested` históricos nem autoriza publicação. Definir política de arquivo/volume, chaves/assinatura, papéis, custódia, retenção, consistência com DB e fluxo de restore **com os responsáveis** antes de qualquer implementação operacional. As 222 exigências continuam rastreadas sem promoção automática.

**Decisão QA: NO-GO** para produção, migração de ledger real, anúncio de backup completo ou habilitação CLI v2. Próximo lote somente após `CONTINUAR`: obter decisão de política de arquivo/chaves/custódia; alternativamente ensaiar download autenticado de bytes sintéticos após restore em ambiente QA sem ultrapassar o recorte autorizado. Nenhum commit, push, merge ou deploy nesta onda.
