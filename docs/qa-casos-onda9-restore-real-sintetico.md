## Ambiente e contenção

`gh api repos/postgres/postgres/tarball/REL_17_9` forneceu a tag de fonte PostgreSQL **17.9** em `/tmp`; `configure --without-readline --without-zlib --without-icu` e `make -C src/bin/pg_dump pg_dump pg_restore` geraram binários `pg_dump (PostgreSQL) 17.9` e `pg_restore (PostgreSQL) 17.9` **somente em `/tmp`**, não incluídos no repositório. O ambiente não continha flex/bison/headers zlib: para compilar apenas estes clientes, as etapas geradoras não usadas foram substituídas no build temporário (FLEX/BISON de placeholder, remoção temporária de `psqlscan.o` da biblioteca frontend); o linker concluiu sem essa referência. O runner usa **`--compress=none`** para o arquivo custom, sem TLS, somente em loopback. **Build excepcional de ferramenta para QA; não é pacote homologado nem instrução de instalação de produção.** Binários e biblioteca dinâmica temporários não persistem entre sessões; rodar novamente exige obter clientes 17 confiáveis. Logs de compilação: `/tmp/qa-wave9-configure2.log`, `/tmp/qa-wave9-build-tools3.log` (fora do Git).

`npm run test:backup-restore:pg` recusou URLs de operador antes de criar cluster; o ensaio positivo só rodou com `QA_PG_DUMP_BIN`/`QA_PG_RESTORE_BIN` apontando aos executáveis 17.9 temporários. O runner criou **um cluster PostgreSQL 17.9 novo em `127.0.0.1`**, com dois bancos novos distintos (`seg_qa_backup_source`, `seg_qa_backup_restored`); o destino não é cópia TEMPLATE. Diretório de arquivo custom e cluster temporários removidos em `finally`. Nenhuma base existente, produção, serviço externo ou dados reais foram acessados.

## Defeitos, lacunas e decisão

- `PLT-DEF-015` (**bloqueio de ferramenta da Onda 8**) ficou **contornado somente nesta sessão de QA** por clientes 17.9 compilados de fonte; um `npm ci` futuro não instala esses clientes. Não prometer runner reproduzível por padrão sem ferramenta gerenciada e auditada.
- A aprovação de `PLT-BAK-001.B` é **parcial e estritamente limitada**: dois bancos no **mesmo cluster efêmero**, não restore entre clusters/ambientes; apenas DB, sem arquivos privados/objeto externo. Nenhuma validação de dump em backup criptografado, chaves, custódia, retenção/descarte, segredos reais, PITR, RPO/RTO, carga/concorrência, integridade de todos os ~497 objetos ou permissões de outros papéis. `--no-owner --no-acl` intencional no teste não prova restauração de ownership/RBAC de produção.
- O arquivo custom temporário é **não criptografado**; contém somente massa sintética e foi removido junto ao cluster. **Não usar este runner como backup de produção.** Checksums de ledgers históricos alterados e upgrade de base legada continuam sem reconciliação; clone TEMPLATE da Onda 5 não é a evidência usada aqui. Auditoria de outras escritas CLI, download privado e cliente v2 ainda não homologados.

**Decisão QA: NO-GO** para produção, migração/restore de banco preexistente e habilitação CLI v2. Próximo lote após `CONTINUAR`: inventariar backup de arquivo privado e fluxos de acesso sem dados reais, planejar restore em *cluster* distinto com binários gerenciados e política/criptografia aprovada; validar ledger histórico somente com inventário e autorização específicos. Não houve commit, push, merge ou deploy.
