## Defeitos, limites e decisão

- `PLT-DEF-024` **aberto**: rollback DB ainda pode deixar objeto órfão até cleanup; falta protocolo transacional/reconciliação. `PLT-DEF-022` **aberto**: objetos usados aqui foram criados pela fixture, **não** recuperados da origem real do CLI v2. O helper compara recibos originais em memória, além da assinatura; âncora criada no mesmo processo QA **não** representa confiança operacional externa durável. Falha pós-verificação durante importação múltipla pode deixar importação parcial; não é commit atômico de DB+FS.
- Não há snapshot DB+FS coordenado sob escrita concorrente, inventário total das famílias privadas, armazenamento WORM/externo, criptografia/KMS/HSM, rotação e cadeia de confiança operacional, replay/rollback protection, WAL/PITR, retenção e RPO/RTO medidos, nem rota HTTP de leitura CLI v2 aprovada. API administrativa de backup permanece 503/fail-closed; nenhum requisito é promovido automaticamente.
- **Decisão QA: NO-GO** para backup/restore operacional, uso de dados reais, publicação ou habilitar CLI v2 a clientes. Permanecem **222 requisitos rastreados**. Próximo lote apenas mediante `CONTINUAR`: discutir e ensaiar, exclusivamente em QA sintético, importação parcial/rollback seguro e classificação de órfãos ou consistência sob falha controlada; qualquer staging real ou teste destrutivo requer autorização específica. Nenhum commit, push, merge ou deploy nesta onda.
